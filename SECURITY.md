# Политика безопасности

## Как сообщить об уязвимости

Не открывайте публичный issue. Используйте GitHub Private Vulnerability
Reporting (вкладка **Security → Advisories → Report a vulnerability** в этом
репозитории). Опишите: версию/коммит, шаги воспроизведения, влияние и, если
есть, PoC. Мы постараемся подтвердить получение и вернуть ответ в разумный
срок. Пожалуйста, дайте время на исправление до публичного раскрытия.

## Поддерживаемые версии

| Версия | Поддержка |
|---|---|
| 0.x (PoC) | только последний коммит main; исправления по возможности |

Проект находится в статусе proof-of-concept: API, формат конфига и протокол
могут меняться без предупреждения.

## Границы применимости

- pgtun — экспериментальный транспорт, а не средство анонимности или защиты
  данных. Он **не аудирован**.
- Данные туннеля хранятся в таблицах PostgreSQL в открытом виде; TLS защищает
  только транспорт.
- Уязвимости в PostgreSQL, pgx, go-shadowsocks2 и других зависимостях
  сообщайте их мейнтейнерам; здесь — только код pgtun.

## Явные предупреждения

- **Не выставляйте PostgreSQL в интернет без необходимости.** Публичный порт
  5432 — это публичная СУБД: сканеры и брутфорс придут быстро. Ограничивайте
  доступ по адресам, используйте сильные пароли и `hostssl`.
- **TLS по умолчанию самоподписанный.** `sslmode=require` шифрует канал, но
  **не защищает от MITM**: клиент не проверяет сертификат. Для защиты от MITM
  используйте `sslmode=verify-full` с `sslrootcert` (файл `server.crt` из
  volume `pgcerts`) или сертификат Let's Encrypt с реальным доменом.
- **Shadowsocks-листенер по умолчанию слушает `0.0.0.0`** в клиентских
  скриптах, чтобы телефон в той же LAN мог подключиться. Порт 8388 доступен
  всей локальной сети и защищён только паролем SS; держите его за firewall или
  переключите на `127.0.0.1` с пробросом.
- **Не используйте pgtun для незаконной деятельности**, обхода ограничений
  там, где это запрещено, и любого абьюза. Ответственность за использование
  лежит на пользователе.
- Учитывайте ToS облачного провайдера: нестандартный трафик к СУБД может
  нарушать правила хостинга.
